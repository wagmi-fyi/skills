# Resume — re-bootstrap the orchestrator after a compaction (or cold re-entry)

When a persistent orchestrator session resumes — its context was **compacted**, or it's picking a dormant orchestration back up — **re-ground into the role and re-derive live state before acting. Trust nothing you didn't just re-verify.** A compaction compresses both the contract and the state; this pass restores both.

> **Whole tmux server gone (crash / reboot), not just this session's context?** You need `operations/recover.md` **first** — it re-stands the substrate (bus pane registrations, push-wake) and relaunches every session; `resume` assumes the server and your pane still exist. `recover` then hands each relaunched orchestrator back to this operation.

## Why a dedicated pass
The `run` loop assumes you already hold the graph + the contract in working memory. After a compaction you don't — the summary is lossy. Skipping the re-ground is how an orchestrator drifts: it starts doing delegate work, trusts a stale report, misses a dead delegate, or deploys against a stale rev. Do this once, at re-entry, then hand off to `run`.

## The re-bootstrap checklist
1. **Re-assert your standing postures FIRST.** Read the workpaper's **Standing Postures** block — the **Effective config** (per-run overrides; honor these *over* `config.yaml` defaults) and the **Behavioral postures** — and re-affirm `method.md`'s core principles as *live directives*, not just re-read prose. A compaction silently resets postures (auto-reap flips back off, "drive/parallelize" fades to over-caution, a run-specific deploy discipline evaporates); re-asserting them here is what stops the drift. A posture proven general gets promoted to a default via `checkpoint` — until then it lives in the workpaper and you re-assert it from there.
2. **Re-read the contract — fully, not the SKILL.md summary.** Re-read `reference/{human-in-the-loop,method,session-bus,substrate,git,decision-briefs}.md` + the operation you drive (`run`). This restores the rules a compaction blurs: the orchestrator *mutates nothing / never builds or deploys itself*; pause only on *design crossroads / human-only-irreversible*; *verify-don't-trust*; *parallelize cognition, serialize commitment*; the 5-part prompt contract; the commitment-lease discipline.
3. **Load `config.yaml`** — `output_dir`, `bus_dir`, `spawn_mode`, `close_mode`, `notify` — then apply the workpaper's **Effective config** deltas on top. Those overrides are the run's *real* settings; the bare `config.yaml` values are only the baseline.
4. **Read the resume surface.** The workpaper's STATUS box + **newest journal entry = "where we are"** + `plan.md` (graph/gates). If the project composes on a host skill's workpaper, that's the surface — don't stand up a duplicate.
5. **Survey the shared bus (read-only)** — `bus handles` + `bus locks`. Confirm your handle. **A commitment lease may have EXPIRED while you were idle — that's benign; never hold one across idle time, re-take it at the next commitment.** Read your own inbox read-only (`bus read <you>`) for anything that landed.
6. **Verify each in-flight delegate's liveness — by pane CONTENT, not the command column.** `tmux capture-pane -p -t <pane>` and read the live output (spinner / todo list / input prompt). ⚠ **A spawned delegate shows `zsh` (or the launch wrapper) in `pane_current_command` even while `claude` runs inside it — do NOT read that column as "dead."** ⚠ **Second trap — the SCROLLED-UP pane:** if the delegate's TUI is scrolled up (a `N new messages ↓` indicator is visible), `capture-pane -p` returns the *frozen visible region*, not the live tail — so a plain capture (and even a same-position double-capture 5s apart) will falsely read "idle/parked." The **reliable liveness signals when scrolled** are the footer **context-token counter advancing** (e.g. `210k → 220k`) and the **`N new messages` count climbing** (`2 → 5`); to see the real latest output, `capture-pane -p -S -250` and read its *true tail*, or scroll the pane to the bottom first. Classify each: *alive + working* (leave it), *parked + waiting* (it needs a signal to resume), *exited / dead* (re-charter a fresh delegate — don't revive a context-blown one; **exception — after a whole-server crash (`recover.md`) every delegate reads exited: there you re-attach each in-flight one via `claude --resume` and let it re-ground, re-chartering fresh only where its lane is unsafe**). **Also sweep for strays:** scan `tmux list-panes -a` for **stale named delegate panes** from prior units (done-but-never-reaped — reap them) and for **text sitting unsubmitted in any pane's input line** (a poke that lost its Enter — submit or clear it deliberately; stranded input is how completion signals silently die and how a "done" delegate reads as "in progress").
7. **Confirm the operational substrate.** Your pane registration matches (`echo $TMUX_PANE` == `bus pane <you>`; `bus init` again if not, so push-wake pokes *you*) **and** push-wake is running (`scripts/bus-watch.sh status`; start it if not). Without both, delegate reports pile up unread and you go blind.
8. **Re-derive load-bearing live state read-only (trust nothing).** The workpaper records what was true *when written*. Before any decision, re-verify the facts it depends on from source-of-truth — deploy rev + image tags, branch/commit shas, DB/PVC state, credential validity, whatever your next step keys on. This is where a stale rev, a reverted tag, or a dead credential gets caught.
9. **Record the resume** in the workpaper (re-grounded; postures re-asserted; what you re-verified; each delegate's status; the lease state; what's next) — so the *next* resume is clean.
10. **Re-enter `run`.** Re-verify any pending delegate reports read-only before trusting them, fan out ready work (parallelize freely), serialize commitments under the lease.

## Durable gotchas (learned the hard way)
- **A compaction resets postures, not just state.** Standing directives (auto-reap on, drive-don't-hoard-ask, deploy-only-from-the-proven-chart) silently revert to skill defaults after a compaction. Re-assert the workpaper's Standing Postures block *first* — that's why `checkpoint` pins it before you compact.
- **Liveness = pane content, not `pane_current_command`.** The `zsh`/wrapper trap will tell you a healthy, building delegate is dead.
- **A scrolled-up pane lies about liveness too.** `capture-pane -p` returns the frozen visible region when the TUI is scrolled up (`N new messages ↓`) — a same-position double-capture reads "idle" even while the session advances. Trust the **context-token counter** + the **new-message count** climbing, or `capture-pane -S -<N>` to read the true tail. (Corollary: cross-check with source-of-truth — e.g. a `helm history` showing the delegate's deploy already landed proves it's well past what its frozen viewport shows.)
- **An idle lease expires — and that's correct.** Re-take at the commitment point; don't hold one across idle time (and don't panic that it lapsed).
- **Parallelize aggressively.** Fan out at the *unit and the phase* level; only the commitment step (deploy / merge-to-mainline / publish) serializes. Post-compaction it's easy to over-serialize out of caution — resist it.
- **Verify-don't-trust survives compaction too.** Re-derive every returning report's gate from source, never the summary — most of all right after a resume, when your memory of "what's already done" is the lossy part.
- **The workpaper is the handoff.** Update it every turn during the run so that *this* pass has something faithful to resume from. A compaction is survivable exactly to the degree the newest journal entry is a real handoff.
